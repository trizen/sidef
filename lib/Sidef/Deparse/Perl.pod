=encoding utf8

=head1 NAME

Sidef::Deparse::Perl - Translates the AST of a Sidef program into Perl code

=head1 SYNOPSIS

    my $deparser = Sidef::Deparse::Perl->new(
        opt              => \%options,
        environment_name => 'Sidef::Runtime',
    );

    my $perl_code = $deparser->deparse($ast);

=head1 DESCRIPTION

This module is the back-end of the Sidef compiler. It receives the abstract syntax tree
that is built by L<Sidef::Parser> and returns a string of Perl code, which is then executed
by C<Sidef::execute_perl()> or written to a file (C<sidef -R perl>, C<sidef -c>).

It is not meant to be used directly: see L<Sidef> (C<compile_code>, C<compile_ast>).

=head1 DESIGN

=head2 Expressions

Every expression of the AST is a hash: C<< {self => OBJECT, ind => [...], call => [...]} >>.
C<deparse_expr()> processes it in three steps:

=over 4

=item 1.

the object itself (C<self>) is handled by a I<node handler>, which is a method named C<_node_*>
selected from the type of the object (see C<%NODE_HANDLERS>);

=item 2.

the indices (C<ind>) are applied: C<_apply_indices()>;

=item 3.

the method calls and the operators (C<call>) are applied: C<_apply_calls()>.
The operators that need special code (assignments, C<==>, C<< <=> >>, prefix operators, etc.) are
handled in C<_special_call()> and C<_unary_operator()>, the others in C<_generic_call()>.

=back

Adding the support for a new type of node means writing a C<_node_*> method and listing it in C<%NODE_HANDLERS>.

=head2 Assembly of the program

The code of a program is assembled by C<_program()> from the following parts:

=over 4

=item header

the pragmas and the options of the program (C<-w>, C<-W>, C<-P>, C<-M>);

=item preamble

the lines that must be executed first, which are collected while the AST is processed:
C<use Module;>, C<use constant NAME =E<gt> ...;>, C<BEGIN> blocks (see C<_prelude()>);

=item declarations

the C<my> declarations of the outermost scope;

=item statements

the program itself.

=back

=head2 Scopes and hoisted declarations

An expression of the AST can declare variables in the middle of a statement (C<if (var x = f()) {...}>), but
a Perl C<my> variable is visible only in the next statements. For this reason, the declarations are
I<hoisted>: they are collected in the scope of the enclosing block (C<_hoist()>) and emitted at the beginning of that block.

A scope is created by C<_with_scope()>, which returns the hoisted declarations followed by the code of the block.

=head2 Names

Every variable, function and class receives a unique number (C<_id()>) that is appended to its name:
C<var x> becomes C<$x_1>. The generated code is deterministic.

The numbers, the constants and the objects that were already emitted are kept by the deparser, which is
therefore reused for C<eval()>: see L</deparse_nested>.

=head2 Constants

The literals (numbers, strings, regular expressions, files, etc.) are created once, as constants
(C<_constant()>), and the equal literals share the same constant.

=head2 Classes

A class is compiled into a single call of C<< Sidef::Object::Class->declare(...) >>. The call receives only
declarative information:

    Sidef::Object::Class->declare(
        key      => ...,        # unique key of the declaration
        package  => ...,        # the Perl package of the class
        name     => ...,        # the name of the class
        type     => 'class',
        parents  => [...],      # the keys of the declarations of the parent classes
        params   => [...],      # the parameters of the constructor
        attrs    => [...],      # the names of the attributes (`has`)
        defaults => sub {...},  # evaluates the default values of the parameters
        build    => sub {...},  # evaluates the attributes
    );

The methods of the class are installed in the package, as usual. Everything else is done at run-time
by L<Sidef::Object::Class>: inheritance (C3), resolution of the fields, constructor and accessors.

The built-in classes that are extended (C<class Number {...}>) don't get a declaration. Their methods are installed
in place, the original method being kept as a fallback for the multiple dispatch.
Structs are classes without inheritance and attributes.

=head1 METHODS

=head2 new

    my $deparser = Sidef::Deparse::Perl->new(%options);

Options:

=over 4

=item opt

the command-line options of C<sidef> (C<-c>, C<-w>, C<-W>, C<-P>, C<-M>);

=item environment_name

the name of the Perl package that contains the generated code (C<main> by default);

=item header, before, between, after

strings that are added to the header, before the code, between the statements and after the code.

=back

=head2 deparse

    my $code = $deparser->deparse($ast);

Returns the Perl code of a program.

=head2 deparse_nested

    my $code = $deparser->deparse_nested($ast);

Returns the Perl code of a piece of code that is deparsed while the program is running (the code of C<eval()>), in the context of the program:
the names, the constants and the declarations that already exist are reused, and the header is omitted.

=head2 deparse_script

    my @statements = $deparser->deparse_script($struct);

Deparses a sequence of statements. In scalar context, it returns the last statement.

=head2 deparse_expr

    my $code = $deparser->deparse_expr($expr);

Deparses one expression.

=head2 deparse_args

    my $code = $deparser->deparse_args(@args);

Deparses a list of arguments and returns it in parentheses: C<(a,b,c)>.

=head2 load_mod

    $deparser->load_mod('Sidef::Types::Array::Array');

Makes the generated program load a Sidef module.
