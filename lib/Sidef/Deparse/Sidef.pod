=encoding utf8

=head1 NAME

Sidef::Deparse::Sidef - Converts the AST of a Sidef program back into Sidef code

=head1 SYNOPSIS

    use Sidef;

    my $sidef = Sidef->new(name => 'example');

    # Parse the code, and deparse the AST
    my $code = $sidef->compile_code('say [1,2,3].map{ _ ** 2 }', 'Sidef');

    # Or: deparse an existing AST
    my $ast  = $sidef->parse_code('var x = 1 + 2 * 3');
    my $code = $sidef->compile_ast($ast, 'Sidef');

From the command-line:

    sidef -r script.sf            # deparse the program (same as: -R sidef)
    sidef -O2 script.sf           # optimize, deparse and parse again

=head1 DESCRIPTION

C<Sidef::Deparse::Sidef> generates human-readable Sidef code from the Abstract Syntax Tree (AST) created
by L<Sidef::Parser>. Its purpose is to show how the parser understands a program, therefore the generated
code never relies on the precedence of the operators: every operator expression that is the operand of
another operator is parenthesized.

    1 + 2 * 3          becomes    1 + (2 * 3)
    10 - 3 - 2         becomes    (10 - 3) - 2
    -x ** 2            becomes    -(x ** 2)
    a < b < c          becomes    (a < b) && (b < c)
    a = b = c          becomes    a = (b = c)
    a and b or c       becomes    (a and b) or c
    x ? 1 : y ? 2 : 3  becomes    x ? 1 : (y ? 2 : 3)
    var z = x + y      becomes    var z = (x + y)

The operands that are atoms (variables, literals, calls, indices, blocks) are not parenthesized.
The expressions that are statements, the arguments of a call, the elements of an array and the conditions
of the control-flow statements are not operands, so they are not parenthesized either. The modifiers
C<if> and C<while> are applied on the whole statement from their left: C<x = 1 if (a && b)>.

The generated code is parsed again into an equivalent AST. It can be used for inspecting
a program, for normalizing its style, and for the optimization level C<-O2>.

The rest of the generated code:

=over 4

=item * uses the infix syntax of the operators, the blocks and the control-flow statements with
indentation, the hyper-operators, the interpolated strings (C<"x = #{x}">), and the implicit topic
calls (C<.method>);

=item * writes the rational numbers as rational numbers: C<Number("3/2")> (they are never converted
into decimal numbers);

=item * keeps the structure of the AST, when the same code can be parsed into different ASTs
(for example C<(a < b) < c> and C<a < b && b < c>, or C<(a = b) += c> and C<a = (b += c)>).

=back

=head2 Precedence

Every expression is deparsed into the pair C<($code, $precedence)>, where C<$precedence> is the binding
strength of the outermost construct of C<$code>, using the precedence levels of L<Sidef::Parser> (see
C<Sidef::Parser::infix_precedence()>). It is used for deciding when the parentheses are required: an operand
that is not an atom is always parenthesized.

=head1 METHODS

=head2 new

    my $deparser = Sidef::Deparse::Sidef->new(%options);

Creates a new deparser. The options are:

=over 4

=item * C<before> - text placed before the code (default: C<''>)

=item * C<between> - text placed between the statements (default: C<"\n">)

=item * C<after> - text placed after the code (default: C<"\n">)

=item * C<class> - the current namespace (default: C<'main'>)

=item * C<indent> - the number of spaces used for each level of indentation (default: C<4>)

=item * C<data_types> - a hash that maps the name of a Perl class to the name of the type in Sidef

=back

A blank line is added around the definitions (functions, classes, ...) and around the multi-line statements
of the top-level, only when C<between> is the default value.

=head2 deparse

    my $code = $deparser->deparse($ast);

Deparses a script (the AST returned by C<< Sidef::Parser->parse_script >>) into code.

=head2 deparse_script

    my @statements = $deparser->deparse_script($ast);

Returns the code of each statement of a script, in list context, or the code of the last statement,
in scalar context.

=head2 deparse_expr

    my $code = $deparser->deparse_expr($expr);

Returns the code of an expression, which is a hash with the keys C<self>, C<call> and C<ind>,
or a script.

=head1 THE AST

    script    = { namespace => [ statement, ... ] }
    statement = { self => OBJECT | script, call => [ ... ], ind => [ ... ] }
    call      = { method => NAME, arg => [ ... ] }       # a method call, an operator or a hyper-operator
              | { keyword => if|while|and|or, arg => [ expr ] }
    ind       = { array => [ statement, ... ] } | { hash => [ statement, ... ] }

The indices are applied before the calls. The operators with the same precedence are stored
in the same list of calls: C<a + b - c> is C<< { self => a, call => [ +b, -c ] } >>.

=head1 NOTES

=over 4

=item * The parser replaces the use of the fields of a class inside a method (C<x>) with C<self{:x}>.
The deparser keeps the explicit form, because it can't know whether a variable with the same name
is visible in that place.

=item * Some objects are written in the function style, such as C<Vector(1, 2)> (instead of C<%v(1 2)>)
or C<Complex(1, 2)>. This gives an equivalent program.

=item * The enumerations (C<enum>) are replaced by their values, as the parser already does.

=item * An interpolated string that contains double quotes inside C<#{...}> is written with
the method C<interpolate>, as there is no way of escaping them.

=back
